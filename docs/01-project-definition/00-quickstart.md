# project definition quickstart

use this section to define the project before writing code. keep each file focused on one decision area so the repo stays easy to scan and update.

## suggested order

1. problem: what pain exists and who feels it.
2. goal: what success looks like.
3. solution: what you will build.
4. dataset: where the data comes from and what shape it has.
5. constraints: what the system must respect.
6. stack: what tools you will use and why.
7. architecture: how the pieces fit together.
8. workflow: how work moves from idea to delivery.
9. structure: what each folder and file is for.
